# 2026-04-18 v1 Benchmark Results

## Run conditions

- Date: 2026-04-18 00:23 CDT
- Model: `gpt-realtime`
- Worker path: local `wrangler dev --local` on `http://127.0.0.1:8787`
- Session config: same worker-minted client secret and same `session.update` contract used by the iOS app after the Phase 3 transport fix
- Audio harness: synthesized speech with macOS `say` (`Samantha` for English, `Kyoko` for Japanese), converted to mono `pcm16` at 24kHz, then streamed over the Realtime WebSocket with `input_audio_buffer.append` / `commit` / `response.create`
- UI verification: the actual iPhone app was separately rebuilt and verified on the iPhone 16 simulator for fullscreen layout, stable connect, and pause/resume behavior

## Ship bar

- EN→JA clean enough: `10/10`
- JA→EN clean enough: `9/10`
- Worst first-delta latency: `0.655s`
- Mean first-delta latency: `0.404s`
- Reconnect loop regression: fixed
- Result: `PASS`

This clears the v1 bar from `docs/implementation-plan.md`: both directions are at or above `8/10`, and first text delta stayed under `1.5s` on every benchmarked run.

## Non-blocking issues observed

- `conversation.item.input_audio_transcription.completed` did not arrive on `7/20` scripted runs even though the translated output still completed correctly.
- The benchmark harness used synthesized speech, not a human speaker on device. That is good enough for a repeatable v1 gate, but it should not be mistaken for a field test in a noisy real-world environment.

## Conclusion

The current build meets the v1 benchmark bar.

The Phase 3 transport bug was a schema issue in the client `session.update` payload: it omitted `session.type = "realtime"`. Once that was fixed, the app stopped falling into reconnect loops and the live session stabilized.

The one follow-up worth watching is JA→EN recommendation phrasing around vague restaurant prompts like `おすすめは何ですか？`. That did not block v1, but it is the clearest candidate for future prompt tuning.
